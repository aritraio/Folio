## 1. Mental Model: How Capacitor Works

If you've never used Capacitor before, think of it this way:

- **What it IS NOT**: It is not Cordova or PhoneGap from 2012. It does not replace your React code, and it does not compile your JavaScript into native Kotlin views like React Native does.
- **What it IS**: Capacitor is a modern, ultra-lightweight native bridge created by the Ionic team. It takes your standard production web build (`dist/` folder generated by `npm run build`), places it inside a native Android Studio project (`/android`), and renders it inside Google's high-performance Android System WebView (powered by Chromium's V8 engine).
- **Native Bridge**: Whenever you need native mobile features (e.g. Biometric Fingerprint Lock, Haptics, Android Share Sheet, or Hardware Back Button), Capacitor provides clean JavaScript APIs that talk directly to Android native code behind the scenes.

## 2. Prerequisites & System Setup (macOS)

Before writing Capacitor commands, ensure your Mac has the standard Android development toolchain installed.

### 2.1 Verify Node.js
Folio requires Node `>= 20.0.0` (Node 22 recommended):
```bash
node -v
npm -v
```

### 2.2 Install Java Development Kit (JDK 17 or JDK 21)
Android's Gradle build system requires Java 17 or 21. Check if you have Java installed:
```bash
java -version
```
If you don't have it or your version is older than 17, install OpenJDK via Homebrew:
```bash
brew install openjdk@17
```
Add Java to your `~/.zshrc`:
```bash
echo 'export PATH="/opt/homebrew/opt/openjdk@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

### 2.3 Install Android Studio
1. Download and install **Android Studio** (Ladybug or newer) from [developer.android.com/studio](https://developer.android.com/studio).
2. Open Android Studio and walk through the **Setup Wizard**.
3. During setup, make sure the following components are checked:
   - **Android SDK Platform** (API 34 or 35)
   - **Android SDK Command-line Tools (latest)**
   - **Android SDK Build-Tools**
   - **Android Virtual Device (AVD)**

### 2.4 Configure Environment Variables in `~/.zshrc`
Open your terminal and paste the following to add the Android SDK to your path:

```bash
cat << 'EOF' >> ~/.zshrc

# Android SDK Path
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/emulator
export PATH=$PATH:$ANDROID_HOME/platform-tools
export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin
EOF

source ~/.zshrc
```

Verify that `adb` (Android Debug Bridge) works:
```bash
adb --version
```

## 3. Step-by-Step: Adding Capacitor to Folio

Now we configure Capacitor inside the Folio codebase.

### Step 1: Install Capacitor Core and CLI
Run this inside your Folio repository root:

```bash
npm install @capacitor/core
npm install -D @capacitor/cli
```

### Step 2: Initialize Capacitor Configuration
Run the `init` command:

```bash
npx cap init Folio com.aritra.folio --web-dir dist
```
- **App Name**: `Folio`
- **Package ID / App ID**: `com.aritra.folio` (must follow standard reverse-domain notation)
- **Web Asset Directory**: `dist` (this matches Vite's build output)

This generates a `capacitor.config.json` (or `capacitor.config.ts`) in your root directory.

### Step 3: Verify / Customize `capacitor.config.json`
Inspect `capacitor.config.json` and ensure it matches:

```json
{
  "appId": "com.aritra.folio",
  "appName": "Folio",
  "webDir": "dist",
  "server": {
    "androidScheme": "https"
  },
  "android": {
    "buildOptions": {
      "keystorePath": "",
      "keystorePassword": ""
    }
  }
}
```

> **Why `androidScheme: "https"` is critical**:  
> In modern Android WebViews, setting `androidScheme` to `"https"` serves your assets from `https://localhost` rather than `http://localhost` or `file://`. This ensures standard web APIs, browser history (`BrowserRouter`), and SVG charts in Recharts work identically to running on the web.

### Step 4: Install the Android Platform Package
Install the official Android platform package for Capacitor:

```bash
npm install @capacitor/android
```

### Step 5: Add the Android Native Project
Run:

```bash
npx cap add android
```
What this does:
- Creates a full-fledged native Android Studio project inside an `/android` directory in Folio.
- Creates `MainActivity.java` with the Capacitor WebView host.
- Generates `AndroidManifest.xml` and Gradle scripts.

### Step 6: Build Your Web App
Capacitor needs your compiled web files. Run Vite's production build:

```bash
npm run build
```
This generates the `dist/` directory containing your bundled HTML, JS, CSS, and fonts.

### Step 7: Sync the Web Bundle to Android
Run:

```bash
npx cap sync android
```
What this does:
1. Copies the contents of `dist/` into `android/app/src/main/assets/public/`.
2. Registers any native Capacitor plugins with your Android Gradle project.

## 4. Running the App on Android (Emulator & Physical Device)

You have two simple ways to launch the app:

### Option A: Via Android Studio (Recommended for Beginners)
Run:
```bash
npx cap open android
```
1. Android Studio will open the `/android` folder.
2. Wait 1–2 minutes for Gradle to index dependencies on the first run (progress bar at the bottom right).
3. In the top toolbar, select a target device:
   - **Virtual Device (Emulator)**: Click **Device Manager** on the right sidebar -> Click **Create Device** (e.g. Pixel 8 with Android 14/15) -> Click the green **Play** button.
   - **Physical Android Phone**: Enable **Developer Options** and **USB Debugging** on your phone, then connect it via USB. Your phone will show up in the top device dropdown.
4. Click the green **Run (▶)** button in the top toolbar. The app compiles and installs on your device!

### Option B: Directly from the Command Line
If you have an emulator running or a phone connected via USB:
```bash
npx cap run android
```

## 5. Supercharging Development with Live Reload

Normally, whenever you make a change in React, you have to run `npm run build && npx cap copy android`.  
**You don't need to do that!** Capacitor supports **Live Reload**, which streams your Vite development server straight into your Android app over Wi-Fi.

### Step 1: Find Your Mac's Local IP Address
In terminal, run:
```bash
ipconfig getifaddr en0
```
*(Suppose your IP is `192.168.1.45`)*

### Step 2: Configure Live Reload in `capacitor.config.json`
Temporarily add the `server.url` property:

```json
{
  "appId": "com.aritra.folio",
  "appName": "Folio",
  "webDir": "dist",
  "server": {
    "url": "http://192.168.1.45:5173",
    "cleartext": true
  }
}
```

### Step 3: Run Vite with Host Binding
Make sure Vite accepts external network connections by editing your `npm run dev` script or running:
```bash
npm run dev -- --host
```

### Step 4: Sync and Run
```bash
npx cap copy android
npx cap open android
```
Now, whenever you edit any file in `src/`, your Android app will hot-reload instantly just like your desktop browser!

> ⚠️ **Important**: Before building the final production APK, remove or comment out the `"url"` line in `capacitor.config.json` so the app loads the embedded offline files again.

## 6. Essential Mobile Polish for Folio

To give Folio a native, premium feel on Android, implement these 4 quick improvements.

### 6.1 Install Core Mobile Plugins
Install Capacitor's official status bar, app lifecycle, and haptics plugins:

```bash
npm install @capacitor/app @capacitor/status-bar @capacitor/haptics
```

### 6.2 Handle the Android Hardware Back Button
By default in Android, tapping the back button or swiping back might close the app. We want it to navigate back through Folio's pages (`/transactions`, `/analytics`, etc.) or close dialog modals first.

Create a mobile initialization hook in `src/utils/useCapacitor.js`:

```javascript
import { useEffect } from 'react';
import { useNavigate, useLocation } from 'react-router-dom';
import { App } from '@capacitor/app';
import { Capacitor } from '@capacitor/core';
import { StatusBar, Style } from '@capacitor/status-bar';

export function useCapacitor() {
  const navigate = useNavigate();
  const location = useLocation();

  useEffect(() => {
    // Only run on native platforms (Android/iOS)
    if (!Capacitor.isNativePlatform()) return;

    // 1. Configure Status Bar
    const isDark = document.documentElement.classList.contains('dark');
    StatusBar.setStyle({ style: isDark ? Style.Dark : Style.Light }).catch(() => {});
    StatusBar.setBackgroundColor({ color: isDark ? '#0A0A0A' : '#FAFAFA' }).catch(() => {});

    // 2. Hardware Back Button Listener
    const backListener = App.addListener('backButton', ({ canGoBack }) => {
      // Check if any modal is currently open in the DOM
      const modalCloseBtn = document.querySelector('[data-modal-close]');
      if (modalCloseBtn) {
        modalCloseBtn.click();
        return;
      }

      // If we are not on the dashboard root, navigate back
      if (location.pathname !== '/') {
        navigate(-1);
      } else {
        // Exit app if on main dashboard
        App.exitApp();
      }
    });

    return () => {
      backListener.then((listener) => listener.remove());
    };
  }, [navigate, location]);
}
```

Call `useCapacitor()` at the top of `src/App.jsx`.

### 6.3 Safe Area Insets & Viewport
Update `index.html` line 6 to prevent unwanted pinch-zoom and support notches:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover" />
```

In `src/index.css`, ensure your layout respects notches and navigation gestures:

```css
/* Safe area padding for modern Android & iOS */
body {
  padding-top: env(safe-area-inset-top, 0px);
  padding-bottom: env(safe-area-inset-bottom, 0px);
  padding-left: env(safe-area-inset-left, 0px);
  padding-right: env(safe-area-inset-right, 0px);
  -webkit-tap-highlight-color: transparent;
  user-select: none;
}

/* Allow text selection inside input fields */
input, textarea {
  user-select: auto;
}
```

### 6.4 (Optional) Add Biometric Authentication (Fingerprint / Face Unlock)
Because Folio is a personal financial ledger, you can easily lock the app behind Android's native biometric prompt using `@aparajita/capacitor-biometric-auth`:

```bash
npm install @aparajita/capacitor-biometric-auth
```

Usage in JavaScript:
```javascript
import { BiometricAuth } from '@aparajita/capacitor-biometric-auth';

async function verifyUser() {
  const available = await BiometricAuth.checkBiometry();
  if (available.isAvailable) {
    const result = await BiometricAuth.authenticate({
      reason: 'Please authenticate to access your Folio ledger',
      cancelTitle: 'Cancel',
    });
    return result.authenticated;
  }
  return true; // Fallback if no biometric hardware is configured
}
```

## 7. Daily Developer Workflow Cheat Sheet

Keep these commands handy for your regular development workflow:

| Goal | Command | Description |
| :--- | :--- | :--- |
| **Normal Web Dev** | `npm run dev` | Runs standard Vite dev server in browser. |
| **Rebuild Web Assets** | `npm run build` | Builds new code into `/dist`. |
| **Update Android Files** | `npx cap copy android` | Copies `/dist` into the Android project (fast). |
| **Sync Plugins & Assets**| `npx cap sync android` | Runs `copy` + updates native Android Gradle plugins. |
| **Open Android Studio** | `npx cap open android` | Launches the native Android Studio project. |
| **Run directly on phone**| `npx cap run android` | Builds APK and launches it on connected device. |

### Convenient `package.json` Scripts
Add these handy shortcuts to your `package.json` under `"scripts"`:

```json
"scripts": {
  "build": "vite build",
  "cap:build": "npm run build && npx cap copy android",
  "cap:sync": "npm run build && npx cap sync android",
  "cap:open": "npx cap open android",
  "cap:run": "npm run build && npx cap run android"
}
```

Now, whenever you want to test your latest web changes on Android, just run:
```bash
npm run cap:run
```

## 8. Building a Standalone APK for Your Phone

When you want to send an `.apk` file to your phone or share it with friends without using the Play Store:

### Step 1: Ensure Local Build is Ready
1. Ensure `capacitor.config.json` has no active `server.url` override.
2. Run:
   ```bash
   npm run build
   npx cap sync android
   ```

### Step 2: Build Debug APK via Android Studio
1. Run `npx cap open android`.
2. In the Android Studio menu bar, click:  
   **Build** > **Build Bundle(s) / APK(s)** > **Build APK(s)**.
3. Once completed, a pop-up appears in the bottom right corner: *"APK(s) generated successfully."*
4. Click **locate**. Your standalone installable `.apk` file will be waiting at:  
   `android/app/build/outputs/apk/debug/app-debug.apk`

### Step 3: Install via ADB directly to your phone (Optional)
If your phone is plugged in with USB debugging:
```bash
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

## 9. Troubleshooting & Gotchas

### Issue 1: "White Screen" on App Startup
- **Root Cause**: Usually caused by a broken JavaScript path in `dist/index.html` or an unhandled client error.
- **Fix**: Open Google Chrome on your Mac while the app is running on your phone/emulator. Navigate to `chrome://inspect/#devices`. Click **Inspect** under your Folio WebView to view the DevTools console and see the exact error message!

### Issue 2: SVG Charts Look Cut Off
- **Root Cause**: Mobile viewports are narrower than desktop monitors. If an SVG chart in Recharts has a fixed width like `width={600}`, it will overflow.
- **Fix**: Always wrap Recharts in `<ResponsiveContainer width="100%" height={300}>`.

### Issue 3: Gradle Build Fails with Java Version Error
- **Root Cause**: Android Studio is using an incompatible JDK version.
- **Fix**: In Android Studio, go to **Settings** (or **Preferences** on Mac) > **Build, Execution, Deployment** > **Build Tools** > **Gradle**. Under **Gradle JDK**, select **Embedded JDK** or **JDK 17**.

### Issue 4: `localStorage` Data Persistence on Android
- **Note**: Folio's data lives in `localStorage`. Android preserves `localStorage` across app relaunches. However, if a user goes to Android System Settings and clicks *"Clear Data"*, `localStorage` will be wiped.
- **Recommendation**: Always encourage users to use Folio's built-in **Settings > Export JSON Backup** to save their ledger files to their phone's local storage.
